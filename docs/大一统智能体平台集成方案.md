# 大一统智能体平台集成方案

> 场景：Jeecg 微服务架构 + 自研 OAuth2 登录；多业务子系统提供工具接口；建设 AI 中台（本仓库）提供智能体运行时。目标是「一个大一统机器人」按意图路由到各领域智能体，且**智能体权限为登录用户权限的子集**。
>
> 版本：2026-10 · 与代码契约冲突时以实现为准。

---

## 1. 背景与目标

### 1.1 现状

| 已有 | 说明 |
| --- | --- |
| Jeecg 微服务 | 多业务子系统 |
| 自研 OAuth2 | 统一登录，各系统自行验签 |
| 用户–角色–资源 | 功能权限（按钮/菜单/权限码） |
| 组织机构 + 数据权限 | 本人/本部门/自定义等范围 |
| 前端隐藏按钮 | 部分接口**无服务端鉴权**（安全债） |
| 智能体雏形 | 各系统已有或拟建 Agent |

### 1.2 目标

1. **大一统机器人**：用户一句话，路由到合适智能体完成任务。
2. **权限不放大**：Agent 可执行 ⊆ 当前登录用户权限；数据范围与组织一致。
3. **低摩擦接入**：子系统用「接入 Skill + Vue 组件 + 注册接口」即可上线。
4. **可治理**：管理员可见全局接口目录；项目经理/技术负责人把领域知识变成智能体。

### 1.3 非目标

- 不重写各子系统业务鉴权与数据权限插件（沿用 Jeecg 体系）。
- 一期不做自动改写存量接口；只保证**进 Agent 的接口**已治理。

## 2. 总体架构

### 2.1 逻辑视图

```text
                    ┌─────────────────┐
                    │ 自研 OAuth2 IdP │
                    └────────┬────────┘
                             │ JWT（各子系统 / 中心）
     ┌───────────────────────┼───────────────────────┐
     │                       │                       │
     ▼                       ▼                       ▼
┌─────────┐           ┌────────────┐           ┌─────────┐
│ 子系统A │           │  AI 中台   │           │ 子系统B │
│ + AiBot │──────────▶│  平台      │◀──────────│ + AiBot │
└────┬────┘  用户token │            │  用户token└────┬────┘
     │                 │ · 多issuer验签             │
     │                 │ · 意图路由                 │
     │                 │ · 权限裁剪                 │
     │                 │ · 工具调用/审计/HITL       │
     │                 └────────────┬──────────────┘
     │                              │
     │         ┌────────────────────┼────────────────────┐
     │         │ Nacos 工具目录     │  管理台             │
     │         │ (接口/意图/风险)   │  (目录/Agent/审核)  │
     │         └────────────────────┴────────────────────┘
     ▼
  业务 API（各自鉴权 + 数据权限）
```

### 2.2 部署形态

| 形态 | 说明 |
| --- | --- |
| **微服务** | Agent Runtime / 编排 / 治理，注册到 Nacos 与网关 |
| **应用** | 管理台 + 大一统对话入口（可独立，也可嵌入门户） |
| **前端组件** | `AiBot` Vue 组件，挂到各子系统页面 |

### 2.3 关键设计决策（已定）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 跨系统 token | **多 issuer 信任 + 原 token 透传** | 子系统不可改；避免换票中心 |
| 工具发现 | **接口扫描 → 意图分类 → Nacos** | 热更新、集中治理 |
| Agent 权限 | **用户权限 ∩ Agent 工具面** | 满足「子集」 |
| 接入方式 | **Skill 接入包 + Vue 组件** | 项目经理可操作 |
| 存量无鉴权接口 | **未治理不得进 Agent 工具** | 控制爆炸半径 |

## 3. 身份与鉴权

### 3.1 问题

- 调用 **Agent 接口**：不能只收「某一个子系统」的票，否则其它系统挂不上。
- 调用 **子系统工具**：不能用「AI 平台自己的票」，否则子系统不认。

### 3.2 方案：多签发方信任池 + Token 透传

```text
子系统页面（用户已登录，持有子系统 JWT）
    → AiBot 组件携带该 JWT 调用 Agent
        → Agent 按 client_id/issuer 选择 JWKS 验签
            → 认出 userId / org / dataScope
                → 调工具时【同一张 JWT】打回该子系统 API
```

**不引入换票中心**（子系统验签规则零修改）。

### 3.3 信任注册表（管理台维护）

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `clientId` | 子系统标识 | `order-app` |
| `issuer` / `jwksUri` | 签发方与公钥 | `https://sso.order/...` |
| `audience` | 允许受众 | `order-api` |
| `userClaim` | 用户主键 claim | `sub` |
| `tenantClaim` | 租户 | `tenant` / `azp` |
| `orgClaim` / `scopeClaim` | 组织与数据范围 | `dept_id` / `data_scope` |
| `tools` | 允许的工具/接口白名单 | `order.query` |
| `enabled` | 开关 | |

> **安全要点：** 仅登记 `client_id` **不能**放行——JWT claim 可伪造。必须 **issuer + JWKS 验签**，再校验 `aud`/`client_id`。未注册 issuer 的 token 一律拒绝。

### 3.4 双轨（与本仓库现状兼容）

| 轨 | 场景 | 凭证 |
| --- | --- | --- |
| 人轨 JWT | 子系统用户 / 门户用户 | 子系统或中心 JWT |
| 机器轨 API Key | 脚本、运维、无 IdP 联调 | `AMP_API_KEY` 等 |

优先级：**有效 JWT > API Key**；`X-User-*` 默认不信任（迁移窗口可开）。

### 3.5 服务间调用

- Agent → 子系统：**透传用户 JWT**（推荐）或网关代付 + 可信用户头（过渡）。
- **禁止** Agent 持有子系统管理员 Token 做业务。
- 管理面（平台自身）用 API Key / 管理角色，与业务用户权限分离。

## 4. 接口目录与 Nacos 注册

### 4.1 流水线

```text
① 扫描     Swagger / 网关路由 / 代码注解
② 补全     功能描述、权限码、读写、数据字段、风险级
③ 分类     按业务意图（查订单、导出报表、提工单…）
④ 注册     Nacos：group=AMP_TOOLS，dataId=tools-{system}.yaml
⑤ 消费     AI 中台拉取/监听 → 转为 Agent 工具
⑥ 裁剪     会话时按用户权限 ∩ Agent 声明工具面
```

### 4.2 工具元数据 Schema（示例）

```yaml
system: order-app
clientId: order-app
tools:
  - intent: order.query
    name: 查询订单
    description: 按订单号/状态查询订单列表（只读）
    method: GET
    path: /api/orders
    params:
      - name: orderId
        type: string
        required: false
      - name: status
        type: string
        required: false
    permCode: order:query
    scope: read          # read | write
    dataScope:
      - dept_id
      - create_by
    risk: low            # low | medium | high | forbidden
    enabled: true
  - intent: order.delete
    name: 删除订单
    method: DELETE
    path: /api/orders/{id}
    permCode: order:delete
    scope: write
    risk: high
    enabled: false       # 默认不进 Agent
```

### 4.3 与本仓库 Nacos 能力对齐

- 复用 `NacosConfigBridge` / Nacos AI Registry 风格：**nacos → local 同步**、失败回退本地缓存。
- 工具可映射为 `HttpBusinessTool` 类工具；MCP Server 作为可选补充。
- 变更监听热更；实例缓存按租户/agent 驱逐（审后下轮生效）。

## 5. 权限模型（核心）

### 5.1 公式

```text
Agent 可执行能力 = 用户功能权限
                 ∩ Agent 声明工具集
                 ∩ 环境策略（租户/只读/禁写/审批）
```

数据可见性：

```text
结果集 = 业务查询 ∩ data_scope_sql(userId, orgId, dataScope, row)
```

### 5.2 执行点

| 阶段 | 动作 |
| --- | --- |
| 会话开始 | 取用户权限码 + dataScope；裁剪注入工具 |
| 模型出参 | 校验工具入参 schema |
| 工具调用前 | **再验**权限码 + 数据范围（防提示词绕过） |
| 写/高危 | HITL 人工确认（ASK） |
| 结束 | 审计：userId、clientId、工具、参数、结果 |

### 5.3 权限码约定

- 与 Jeecg **按钮权限码同一套**（一码一事）。
- 工具元数据声明 `permCode`；无码或未授权 → 工具不暴露 / 调用 403。
- 角色示例可沿用平台侧：`tenant_admin` / `developer` / `auditor` / `agent_caller`，并映射 Jeecg 角色编码。

### 5.4 数据权限

- **过滤放业务 SQL/插件**（与现有 Jeecg 数据权限一致）。
- Agent/网关只传 `dataScope + orgId + userId`，禁止模型「自行限制范围」。
- 导出、汇总、跨部门查询同样受约束；禁止空条件全表工具进入目录。

## 6. 大一统机器人

### 6.1 职责

| 做 | 不做 |
| --- | --- |
| 意图识别、多 Agent/工具路由 | 不新增用户权限 |
| 会话上下文、多轮 | 不代替业务鉴权 |
| 结果汇总、追问 | 不直接改库 |
| 触发 HITL 审批 | 不用超管 Token |

### 6.2 路由方式（两层）

1. **意图 → 工具**（Nacos 目录里的 `intent`/`description`）
2. **意图 → 子 Agent**（管理台配置的领域智能体，如「订单助手」）

一期可先「总机 + 工具」；二期再拆多 Agent 编排。

### 6.3 Vue 组件 `AiBot`（子系统挂载）

```vue
<template>
  <AiBot
    :token="accessToken"
    client-id="order-app"
    :user-id="userId"
    :org-id="deptId"
    :data-scope="dataScope"
  />
</template>
```

- 位置：页面**左下角**悬浮（可配置）。
- 职责：对话 UI、携带当前登录 token、发起流式会话、展示审批。
- **禁止**前端写死平台 API Key。
- 组件由接入 Skill 提供，样式可主题化。

## 7. 接入 Skill（子系统自助上线）

### 7.1 交付物

| 产物 | 说明 |
| --- | --- |
| `SKILL.md` | 步骤：注册信任表、扫接口、填描述、挂组件、验收 |
| Vue 组件包 | `AiBot` + 挂载示例 |
| 接口扫描脚本 | 从 Swagger/OpenAPI 生成 `tools-*.yaml` 草稿 |
| 配置模板 | issuer/jwks/clientId/工具白名单 |
| 验收清单 | 越权 403、只读、审计有记录 |

### 7.2 项目经理 / 技术负责人再补

- 领域提示词、SOP、口径、禁止事项  
- 从目录**勾选**工具（禁止手写任意 URL）  
- 示例问答（对齐意图）

### 7.3 上线门禁

1. 信任表已注册且验签通过  
2. 工具描述完整、权限码正确  
3. `risk=high` 默认 `enabled=false` 或强制 HITL  
4. 越权用例通过

## 9. 存量「只藏按钮、无鉴权」接口治理

### 9.1 原则

> **未治理接口禁止进入 Agent 工具目录。**  
> 前端隐藏不是安全控制；Agent 会放大暴露面。

### 9.2 分期

| 期 | 动作 |
| --- | --- |
| 立即 | 扫描网关日志 + 代码，产出无鉴权清单；标读写与敏感级 |
| 接入前 | 凡入 Agent 的写/导出/删/权限类，先补服务端鉴权 |
| 中期 | 网关统一权限码拦截；新接口默认拒绝；按钮码=接口码 |
| 长期 | CI 越权测试；403 异常告警；目录收敛 |

### 9.3 过渡保护

- 默认只读工具进 Agent  
- 写操作 HITL  
- 工具网关白名单 + 审计

## 11. 实施里程碑

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| **M1 身份** | 多 issuer 注册与验签；1 个子系统 token 调 Agent 成功 | 非法票 401；合法票认出 userId |
| **M2 透传工具** | 2～3 个只读接口进目录；原 token 调通业务 | 越权用户调用 403 |
| **M3 权限子集** | permCode 裁剪 + 调用前校验 + 审计 | 无权限工具不可见 |
| **M4 机器人组件** | `AiBot` 左下角挂载；意图路由 | 子系统页面可对话查单 |
| **M5 目录与 Nacos** | 扫描脚本 + 意图分类 + 热更 | 新工具上架无需发版 Agent |
| **M6 管理台** | 全局目录、智能体编排、审批 | PM 自助发布领域 Agent |
| **M7 接口治理** | 高危接口补鉴权、网关强制 | 清单下降、CI 越权门禁 |

## 12. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 伪造 client_id 绕过 | 必须 JWKS 验签 + aud；白名单 issuer |
| Agent 放大权限 | 工具裁剪 + 调用前校验 + 业务侧再鉴权 |
| 数据越权 | dataScope 进 SQL；禁全表无过滤工具 |
| 危险写接口 | `risk=high` 默认关闭 / HITL |
| 描述质量差导致乱路由 | 管理员审核描述；意图与权限码分字段 |
| token 过期导致长任务失败 | 组件侧静默续期；失败明确提示重新登录 |
| 子系统 token 算法/claim 不一致 | 信任表 claim 映射 per client |

## 13. 检查清单（上线前）

- [ ] 每个接入子系统：issuer + JWKS + client_id + aud 已注册  
- [ ] 用户 token 透传调用业务成功，且**无超管账号**  
- [ ] 工具均有 `permCode`、`scope`、`risk`  
- [ ] 无权限用户：工具不可见且直接调 403  
- [ ] 数据范围：跨部门数据不可见  
- [ ] 写操作有 HITL 或明确业务审批  
- [ ] 审计可按 userId + clientId 检索  
- [ ] 未治理接口未进工具目录  
- [ ] `AiBot` 仅在挂载页使用用户 token，无平台密钥  

---

## 14. 附录：一句话总结

**管理员治理全局接口目录与信任；业务负责人用目录拼领域智能体；子系统用 Skill + Vue 组件接入；机器人始终以「当前登录用户」的 token 调用原系统——权限是子集，不是放大。**

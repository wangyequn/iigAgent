# 平台工具清单与智能体分工

> 扫描范围：本仓库 `platform-runtime` / `platform-governance` / `platform-open-api` / `amp-starter`  
> 依据：`AgentInstanceFactory` 装配、`CatalogBootstrap` 种子、`@Tool` 声明、`ToolPolicyProperties`  
> 用途：规划「登录平台接入」时的 Agent 建设与工具治理

---

## 1. 结论速览

| 项 | 数量 | 说明 |
| --- | --- | --- |
| **已播种智能体** | **2** | `demo`（默认业务/演示）、`console-bot`（小助） |
| **建议再建智能体** | **3～4** | 业务助手、知识问答、运维审计、（可选）编排总机 |
| **内置工具（常驻/按需）** | **约 25+** | 示例 2 + 知识 1 + 控制台 17 + 沙箱 1 + 记忆 2 + 开关类若干 |
| **动态工具面** | 不定 | HTTP 业务工具、MCP（`enableTools` 过滤）、AgentScope 2.0 开关 |

**建议智能体总数：5～6 个**（2 已有 + 3～4 新建），按「角色职责」拆，不按页面拆。

## 4. 建议创建的智能体（职责分工）

> 原则：**一个 Agent 一个清晰角色**；工具面最小够用；写操作默认 HITL；业务权限 ⊆ 登录用户权限。

```text
                    ┌─────────────────┐
                    │  用户 / 业务页   │
                    └────────┬────────┘
           ┌─────────────────┼─────────────────┐
           ▼                 ▼                 ▼
    ┌────────────┐   ┌────────────┐   ┌────────────┐
    │console-bot │   │biz-assist  │   │knowledge-qa│
    │ 平台运维   │   │ 业务助手   │   │ 知识问答   │
    └────────────┘   └────────────┘   └────────────┘
           │                 │                 │
           └────────────┬────┴────────┬────────┘
                        ▼             ▼
                 ┌────────────┐ ┌────────────┐
                 │ ops-auditor│ │ (可选)     │
                 │ 运维审计   │ │ orchestrator│
                 └────────────┘ └────────────┘
```

### 4.1 已有 · 保留

| Agent ID | 名称 | 作用 | 建议工具面 |
| --- | --- | --- | --- |
| `demo` | 演示 Agent | 开发/联调/契约测试；OpenAPI 调试 | Sample + Knowledge；可临时开危险工具验 HITL |
| `console-bot` | 小助 | 控制台运维副驾、平台问答、UI 导航 | ConsoleBot 全套 + Knowledge +（Sample 可留） |

### 4.2 新建 · 推荐（对接登录平台优先）

| Agent ID | 名称 | 作用 | 建议工具面 | 权限 |
| --- | --- | --- | --- | --- |
| **`biz-assist`** | 业务助手（登录平台） | 页面悬浮助手：查我的工单/待办/用户信息等**业务问答 + 只读工具** | `knowledge_search` + HTTP 业务工具（`user_token`）+ `safe_lookup` | 只读 ALLOW；写/导出 ASK |
| **`knowledge-qa`** | 知识问答 | 制度、手册、操作指引纯知识助手（无写工具） | 仅 `knowledge_search`（+ 可选 Mem0） | 全只读 ALLOW |
| **`ops-auditor`** | 运维审计助手 | 运维侧：用量、审计、会话、健康（可复用 ConsoleBot 查询面，**不要 UI 指挥权**） | `platform_status` / `usage_summary` / `list_audit` / `list_agents` 等只读子集 | 只读 ALLOW；无 `ui_*`、无写 |

### 4.3 可选 · 二期

| Agent ID | 名称 | 作用 | 依赖 |
| --- | --- | --- | --- |
| **`orchestrator`** | 大一统总机 | 意图路由到领域 Agent / Workflow | Workflow + Team + 多 Agent 工具面 |
| **`approver-bot`** | 审批助手 | 汇总 HITL 待办、生成确认建议（**不代替人点确认**） | `list` 类只读 + 审批 API |

### 4.4 不建议单独建的 Agent

| 想法 | 原因 |
| --- | --- |
| 按页面各建一个 Agent | 碎片化；应用 `ui_navigate` + 同一 `console-bot` |
| 「万能写手」Agent | 权限面过大；写操作应落在业务助手 + HITL |
| 每个业务微服务一个 Agent | 一期过重；先 `biz-assist` + HTTP 工具目录，二期再拆领域 |

## 6. 落地步骤（接登录平台时）

1. **目录**：管理台新建 `biz-assist` / `knowledge-qa`（系统提示词写清职责边界）。  
2. **工具**：首批 2～3 个只读 HTTP 工具登记 `business_tool`，`authMode=user_token`。  
3. **权限**：`biz-assist` 对业务工具 ALLOW；写类 DENY 或 ASK；`knowledge-qa` 仅 `knowledge_search`。  
4. **前端**：登录平台挂 `AiBot`，默认 `agentId=biz-assist`；平台问题可路由到 `console-bot`。  
5. **验收**：无权限用户看不到/调不了对应工具；写操作 HITL；审计含 username + tool + params。

---

## 7. 一句话总结

**平台内置约 25+ 工具（示例/知识/控制台 17/沙箱/记忆/HTTP/MCP），已播种 `demo` + `console-bot`；建议再建 `biz-assist`（业务）、`knowledge-qa`（知识）、`ops-auditor`（只读运维）共 3 个，加可选总机约 5～6 个 Agent——按角色分工，工具最小够用，写操作一律 HITL。**
